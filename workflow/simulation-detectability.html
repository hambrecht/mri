Simulating surveys with spatially varying detectability

Author

Leonard Hambrecht, IRSS, University of British Columbia

Published

September 1, 2026

Introduction

In the RMNP survey, moose were harder to detect under dense canopy: the detection function with canopy cover (pabove2) was clearly better supported than one without it. Detectability therefore varies across the landscape, and so does the proportion of animals a survey misses. Whether this matters depends on the design. A design across the whole park samples all canopy conditions in proportion to their area, but subplots may by chance fall in denser or more open forest than the park as a whole.

Simulations normally draw detectability from a fixed detection function, or from individual covariates such as group size that are unrelated to location. The fork of dsims adds spatial covariates: make.detectability() takes a raster through the new cov.surface argument, and at every repetition reads the raster at each simulated animal’s location. The animal’s scale parameter is then

\[\log(\sigma_i) = \log(\sigma_0) + \beta z_i,\]

where \(z_i\) is the raster value at the animal, \(\beta\) the coefficient in cov.param, and \(\sigma_0\) the scale parameter. This is the same log-linear form that Distance uses for covariates, so the fitted coefficients can be used directly. This article is the first documentation of the feature.

The covariate surface

The raster is read at the animals’ x and y coordinates, so it must be in the same CRS as the region. We project the canopy cover layer and write it to a GeoTIFF. A file path is better than an in-memory raster for parallel runs, because each worker then reads the file itself instead of receiving a copy of the raster.

canopy <- rast(here("data", "RMNP", "lidar", "lidar_pabove2_zmax_30m.tif"))[[1]] |>
  project(paste0("EPSG:", LOCAL))
names(canopy) <- "pabove2"
canopy_file <- here("workflow", "outputs", "pabove2_local.tif")
writeRaster(canopy, canopy_file, overwrite = TRUE)

Animals outside the raster, here the 3.5% of the park without lidar data, get the raster mean, and dsims warns when this happens.

Detectability that depends on canopy

We use the fitted hazard-rate detection function for moose: the scale parameter at zero canopy cover (scale_moose), the shape parameter, and the canopy coefficient beta_pabove2. The name of the entry in cov.surface must match the name in cov.param.

detect_canopy <- make.detectability(
  key.function = "hr",
  scale.param = scale_moose,
  shape.param = shape,
  cov.param = list(pabove2 = beta_pabove2),
  cov.surface = list(pabove2 = canopy_file),
  truncation = TRUNCATION_M
)
plot(detect_canopy, pop_desc)

A single simulated survey shows the covariate at work. The canopy value at each detected animal is carried into the survey data, where the analysis can use it.

set.seed(2025)

Analyses

Each simulated survey is analysed in two ways. The first ignores canopy (~1) and relies on pooling robustness: the property that a detection function without covariates can still estimate density without bias when detectability varies between animals (Buckland et al. 2001). The second offers AIC a choice between ~1 and ~pabove2, as in the real analysis. Both use the hazard-rate key.

analysis_null <- make.ds.analysis(dfmodel = ~1, key = "hr", truncation = TRUNCATION_M)
analysis_canopy <- make.ds.analysis(dfmodel = list(~1, ~pabove2), key = c("hr", "hr"),
                                    truncation = TRUNCATION_M, criteria = "AIC")

For the subplot designs, the subplots are strata of the design but should be analysed together, like the grouped strata in the dsims article Grouped strata. group.strata maps every subplot to a single analysis stratum.

group_all <- data.frame(design.id = sub_region@strata.name, analysis.id = "subplots")
analysis_null_sub <- make.ds.analysis(dfmodel = ~1, key = "hr", truncation = TRUNCATION_M,
                                      group.strata = group_all)
analysis_canopy_sub <- make.ds.analysis(dfmodel = list(~1, ~pabove2), key = c("hr", "hr"),
                                        truncation = TRUNCATION_M, criteria = "AIC",
                                        group.strata = group_all)

Running the simulations

Six simulations combine the three designs with the two analyses, each with 100 repetitions. Every repetition generates a new population, a new set of transects and new detections, and fits the detection function. The simulations run in parallel and take several minutes each; for your own designs, start with 20 repetitions to check the setup.

REPS <- 100
set.seed(2025)
run <- function(design, pop, analysis) {
  sim <- make.simulation(reps = REPS, design = design, population.description = pop,
                         detectability = detect_canopy, ds.analysis = analysis)
  run.simulation(sim, run.parallel = TRUE)
}

scenarios <- data.frame(
  design = rep(c("whole park, systematic", "subplots, systematic", "subplots, zigzag"), each = 2),
  analysis = rep(c("~1", "AIC: ~1 or ~pabove2"), 3)
)
sims <- list(
  run(design_full, pop_desc, analysis_null),
  run(design_full, pop_desc, analysis_canopy),
  run(design_sys, pop_desc_sub, analysis_null_sub),
  run(design_sys, pop_desc_sub, analysis_canopy_sub),
  run(design_zz, pop_desc_sub, analysis_null_sub),
  run(design_zz, pop_desc_sub, analysis_canopy_sub)
)
saveRDS(list(scenarios = scenarios, sims = sims), here("workflow", "outputs", "simulations.rds"))

Results

We compare the designs on density, because the subplot designs estimate density within the subplots, not across the whole park. For each simulation we extract the true and mean estimated density (animals per km²), the bias, the root mean squared error relative to the true density (RRMSE), the proportion of 95% confidence intervals that contain the true value, and the mean coefficient of variation.

sim_metrics <- function(sim) {
  s <- summary(sim, description.summary = FALSE)
  D <- s@individuals$D
  D <- D[nrow(D), ] # the total, or the single analysis stratum
  data.frame(
    true_D = D$Truth * 1e6,
    mean_D = D$mean.Estimate * 1e6,
    bias_pct = D$percent.bias,
    rrmse = D$RMSE / D$Truth,
    ci_coverage = D$CI.coverage.prob,
    mean_cv = D$mean.se / D$mean.Estimate
  )
}
results <- cbind(scenarios, do.call(rbind, lapply(sims, sim_metrics)))

With 100 repetitions, the Monte Carlo standard error of the bias is about one percentage point: the standard deviation of the estimates divided by \(\sqrt{100}\). Differences in bias of a point or two are therefore not meaningful.

  • Bias. The bias ranges from -0.2% to 2.4%. That is small next to the CV of about 10% of a single survey, and no design or analysis stands out.
  • Ignoring canopy. Even when detectability depends on canopy, a detection function without covariates (~1) estimates density as well as one with it. This is pooling robustness at work: the detection function averages over the variation in detectability, and because each design samples canopy conditions in proportion to their extent in the area it estimates for, the average is the right one (Buckland et al. 2001). Pooling robustness does not protect estimates for parts of the area with different canopy, such as density in dense forest alone (Rexstad et al. 2023).
  • Including canopy. AIC chose the canopy model in 72–83% of repetitions. Including it changes neither the bias nor the RRMSE materially, so for the overall density it does not make the estimate more accurate.
  • Precision. The RRMSE ranges from 0.09 to 0.11. The subplot designs estimate density within the subplots about as precisely as the whole-park design estimates it for the park, with less effort.
  • Confidence intervals. Coverage ranges from 0.92 to 0.96. With 100 repetitions, coverage itself has a Monte Carlo standard error of about 0.02, so this is consistent with the nominal 95% for all designs.

The estimates from each repetition are stored in sim@results$individuals$D, an array of strata × statistics × repetitions. Its last two slices hold the mean and standard deviation across repetitions, and the last row is the total.

Discussion

For moose in Riding Mountain National Park, drone surveys confined to subplots sized for one flight estimate the density within the subplots as accurately as a design across the whole park. They do this with about 13% less transect, and the zigzag spends the largest share of flying time on effort (Survey designs with subplots). Canopy-dependent detectability, simulated here with the cov.surface argument, did not bias any design. Ignoring canopy in the analysis was also safe for the overall density.

Two caveats matter when using these results for planning:

  • The estimate is for the subplots, not the park. Here the subplots happen to have almost the same density as the park, but that is not guaranteed. To estimate abundance for the whole park from subplots, the survey data have to be modelled with a DSM, predicting from habitat covariates as in Fitting a density surface model.
  • The results are specific to this landscape. The effect of spatially varying detectability depends on how canopy is distributed and where the transects fall. In denser forest, or with subplots placed in unrepresentative habitat, the conclusions could change. Checking that is exactly what cov.surface makes possible.
